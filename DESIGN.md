# 代码工作台

Top layout: the supplied Tellyn logo sits outside the search field on its left. Search is the first row, with a magnifier inside the field and icon-only pin/refresh actions with accessible labels. A horizontal project tab bar follows, with a persistent plus button at its right. The plus button creates and selects a New Project draft tab; its form appears only in that tab. Saving renames it to the folder name. Right-clicking a project tab opens its removal menu. Only the selected project's panel is visible. Project tabs are text on a horizontal rule; the selected tab has a dark underline and larger type. Project headings are omitted below the tabs. Arrow keys, Home and End navigate tabs. Expanded content follows the supplied application-list references: pale gray canvas, white rounded branch cards, quiet leading icon tiles, pill navigation, generous spacing and strictly neutral grayscale values; no tinted accents, decorative header copy or large overview block.
Chinese local Git evidence dock. It starts as a 72 × 180px rounded status tile attached near the top-right edge of the monitor work area and stays visible across macOS workspaces. Hover or click expands it leftward to 460px; leaving collapses it after a short 140ms grace period unless the user chooses 固定展开. Synthetic leave events that still report a pointer within the window are ignored. Native width, height and top position animate together over 340ms with smooth acceleration and deceleration and a fixed right edge. Content fades and slides gently without reflow; reduced-motion preference disables both animations. Collapsed content remains mounted but inert. The strip shows risk worktrees, branches with current coding evidence, and branches merged into the configured local base. macOS-like grayscale palette: light background #f7f7f7, surface #ffffff, ink #1d1d1d, secondary #707070, line #e5e5e5; dark mode uses #1c1c1c and #282828 surfaces. No decorative accent color. System Chinese sans for content; system monospace for paths, SHAs and evidence captions. CSS tokens live in src/styles.css.

Expanded view groups local branches under each project and defaults to all local branches, including the base and merged branches, ordered strictly by latest commit time descending. Unknown commit times sort last; ties use branch name. The user can hide unchecked or merged branches explicitly. Each branch shows its latest commit, coding evidence, local merge evidence and exact running SHA deployment evidence. The worktree evidence card remains behind a native details control. Unknown and failed evidence never becomes success; missing or mismatched deployment evidence remains explicit. GitHub PR/CI evidence loads per worktree; Tellyn deployment evidence loads for six environment × service pairs when the panel expands. Search/filter state is transient. Branch ancestry and feature relationship lines remain exploratory: Git cannot reliably reconstruct a branch's original parent after rebases, cherry-picks or squash merges, so the UI must not invent a parent.

Desktop app icon: the original company vector mark in white on a black rounded square, with transparent outer padding for macOS. Source is src-tauri/icons/appIcon.svg; Tauri generates the bundled ICNS, ICO and PNG sizes. The in-panel logo keeps its existing treatment.

Branch cards use one compact three-step evidence track for commit, local merge and deployment. Each completed step has a solid blue dot; a blue connector appears only between adjacent completed steps. Incomplete, unknown and delegated steps stay hollow. The visible track shows only the three step names; tooltips and accessibility labels retain the precise evidence. Redundant status badges and second-line explanations are omitted. Coding activity is a small pulsing blue dot by the branch name. A top-right downward triangle opens the branch's detailed evidence inline. Deployment is delegated to the release branch for ordinary feature branches; an exact verified runtime SHA can still mark a feature commit as running. The track does not claim all branches must reach deployment.

The project-level deployment evidence disclosure uses the same white rounded card, 18px internal padding and quiet shadow as a branch card. Its summary stays inside the card and has a trailing triangle; expanded evidence begins below an inset divider.

Active coding evidence appears as a small blue dot with a restrained pulse beside the branch name; reduced-motion settings keep the dot still. Idle non-base branches with verified dirty worktrees offer Commit / Push in the card footer. The inline review lists changed files with all selected by default, allows deselection, and requires a commit message. The backend rechecks the registered worktree, branch, HEAD and reviewed change snapshot, commits only selected paths, then pushes without force. A successful commit with a failed push remains visible with a retry action. Clean, unmerged feature branches offer Create PR. The user explicitly selects a remote target branch, can edit title/description and choose draft, and sees if the source must first be pushed. Existing PRs to the selected target are reused. No commit, push or PR mutation runs until its final form action is clicked.

The PR target picker uses the macOS native select popup; platform-owned popup geometry is acceptable for this local desktop tool. Its ownership is recorded in premium-ui.json. The description field keeps a fixed height and scrolls internally for long text.
